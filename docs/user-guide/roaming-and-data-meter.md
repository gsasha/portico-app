# Roaming block and the mobile-data meter

What the app holds back on a roaming plan, how roaming is decided, and how the mobile-data meter in Settings counts.

Ported from the intercom app (0.31.0 meter, 0.33.0 to 0.35.6 roaming). Pure decisions are in `:core` (`core/roaming`, `core/traffic`, JVM-tested); the Android side is `roaming/AndroidRoaming` and `roaming/AndroidTraffic`.

- **What is held back on a roaming plan:** the picture, that is live video (WebRTC and RTSP) and still-picture requests, on Home, the ring screen and the in-call screen. Each usable tile shows "Roaming: tap to show" and a chip; one tap allows pictures for the rest of the trip. **Never held back:** the ring and push, the link to Home Assistant and its commands, the doors' buttons, call audio. There is no setting to turn the block off (the intercom app had none); it is always on.
- **"Roaming" is three tests** (any one means away): `NET_CAPABILITY_NOT_ROAMING` absent on the default mobile network, `TelephonyManager.isNetworkRoaming`, or the serving network's country differing from the learned home country (a local travel eSIM is not roaming but is not home). No new permission. Order matters (`RoamingRules`): the house LAN (link up over the direct path with a Wi-Fi present) ends the question first; no default network holds the last verdict ("don't know" is not "home"); any Wi-Fi or cable is never metered; unknown country with no flag errs towards showing the picture. Fails open on any error.
- **The home country is learned**, never set by hand: recorded the first time the phone is provably at home with a serving country. It starts empty, and until then only the two flags can block (the local-eSIM case needs one prior visit home). **The tap lasts for the trip** (until the verdict says not away), is held in memory only, and a restarted app starts blocked again.
- **The meter** (Settings, "Mobile data used by this app"): today, this month, since reset, each as total / video / calls / everything else, with a Reset button. The total is Android's own count for this app (`TrafficStats` for the UID, includes tunnel overhead) charged to mobile only for intervals when the default network was mobile; video (RTSP payload, camera stills) and calls (frames over the link) are counted by the app, "everything else" is the remainder. Stored as at most 62 day rows plus a running since-reset total (`portico_traffic` prefs). Not counted: bytes while the process is dead (at most the last minute), and WebRTC at home (Wi-Fi).
- **Unverified without a phone:** that the three roaming signals report as they did on the intercom's phone, that `TrafficStats` returns a UID count on the target device, and the chip/notice layout on a small tile.

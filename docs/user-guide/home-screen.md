# Home: cameras and buttons

What the Home screen shows (the cameras and buttons Home Assistant built for this phone), how tiles, sizes, zoom, pages, button icons and colours behave, what the connection status dot means, and what happens when the phone is not connected. Talk, call buttons and house calls are on [their own page](talk-and-house-calls.md); live video is on [Live video](live-video.md).

## The screen, button icons, blocks and colours

The launcher opens **Home** once the phone is enrolled (an HA address and a token); before that it opens
Settings. Home shows what Home Assistant built for this phone (edited in the Portico panel in the Home Assistant
sidebar): a tile per camera with a picture, and a button per action. The top line is the title, the
connection status (tap it for Settings) and a menu button at the top right whose menu is **Settings** (the screen that was called "Setup" before), **Status** (connection and push checks), **About** (version, build type,
whether the tailnet client is built in; no network) (no Reset camera sizes since 0.6.57-alpha: each tile's resize and gear menus change its size and stream). The whole screen scrolls.

- **Button icons.** A button draws an icon before its text (the text always stays). The icon is the one
  the plugin stores for the button (`mdi:door-open`), else a default for its kind (door relay: door-open,
  lock: lock-open-variant, button: gesture-tap-button, script: script-text, scene: palette), else none. The
  app bundles 118 icons from Material Design Icons (`@mdi/svg` 7.4.47, **Apache-2.0**, notice in
  `third_party/mdi/`) as VectorDrawables, generated by `tools/gen_mdi_drawables.py` from the list in
  `core/src/test/resources/icons_v1.json`. That file is a copy of `contract/icons_v1.json` in portico-ha
  (the plugin's picker offers exactly this list); `HomeIconsTest` fails if the copy and
  `HomeIcons.CURATED` disagree or a key has no drawable. To add an icon: add the name to the JSON in both
  repos and to `HomeIcons.CURATED`, then run the script (its docstring says how to fetch the SVGs).
  The Home top line's hamburger menu button (`ic_menu_hamburger`, MDI `menu`) is screen furniture, not a button
  icon: the same script generates it from its separate `CHROME` list, and it is not in `icons_v1.json`.
  The top line's title is the home's name when the plugin sends `home_name` in the `portico/content/get`
  result (plain text, at most 40 characters), else `Portico`; Home has no system action bar.

- **Blocks and button colours (0.5.3-alpha).** A page is drawn block by block: a heading (the block's title), a camera
  grid (a `big` camera a full row, `small` ones two to a row, an odd one half width, left-aligned; `:core`'s `CameraGrid`),
  and rows of buttons (four units a row, a text button two, an icon-only one a 56 dp square of one; `ButtonRows`). A page
  from a server that sends no `blocks` is wrapped into one untitled block, the first camera big and the rest small. A
  button's `color` is one of eight palette names (`palette_v1.json`, a copy of portico-ha's; `ButtonPalette` holds the
  values, a light and a dark swatch each, chosen by the system theme); a button that is off is grey whatever its colour,
  with the server's reason under its row where it gave one (Talk: see [Talk and house calls](talk-and-house-calls.md)). The
  `show_label: false` setting hides the text when there is an icon. To change a colour: change it in portico-ha, copy the
  file, update `ButtonPalette` and the pin in `ButtonPaletteTest`.

## Camera sizes, zoom, pictures, connection status

- **Shrinking a camera keeps what follows it (0.5.5-alpha).** A tap flips the size at once, but the grid is now rebuilt
  just after the tap's own touch is over (not inside it), every still of the page is asked for again, and the whole
  list is laid out afresh; 0.5.4 could leave the cameras and buttons after the tapped tile missing.
- **Camera sizes and pinch zoom (0.5.4-alpha).** A tap on a camera tile flips it big/small at once (offline too; nothing
  is sent) and the phone remembers the choice per page and camera id across launches (`SizeMemory`, its own prefs file
  `portico_sizes`). Home Assistant's `size` (or the first-big auto rule) is only the default: a choice is stored only
  while it differs from it, and it is dropped when HA changes that camera's default (the phone is not stuck on an old
  choice) or removes the camera (only on a real, non-empty answer). The resize menu on the tile changes it back (the old
  menu item **Reset camera sizes** was removed in 0.6.57-alpha); nothing here edits HA. A pinch zooms the picture inside the same tile, 1x to 4x, session only (page change, leaving the
  screen, rotation and a size flip all end it); one finger pans while zoomed, bounded so the picture covers the tile. A
  tap while zoomed returns to 1x instead of flipping the size; there is no double tap. The page swipe is off while any
  tile is zoomed and whenever a second finger touched. TalkBack gets "Make it small/big", "Zoom in", "Zoom out" and
  "Reset zoom" on each tile. Pictures are asked for at `StillWidth`: small 1x the server default (640), big 960, zoomed
  1.5x 1280, zoomed 2.5x 1920 (the server's cap, `ContentCommands.SNAPSHOT_WIDTH_MAX`); a zoomed still costs roughly
  150 to 230 KB/s while someone is pinching [estimate]. Stills are decoded with `inSampleSize` (`ImageSampling`) to
  about the tile's pixels, never above 2.5 megapixels. Gesture rules are `:core`'s `TileGesture` and `SwipeGuard`; the
  pixels, the matrix and the touch plumbing (`TileTouch`, `StillTiles`) can only be seen on a phone.
- **Partial view (tablet / panel mode only).** The resize menu of a camera that shares its block with others also offers
  Partial: that camera big at two thirds of the width, with up to two other cameras of the block (the first two in block
  order) small, stacked at its right; the rest of the block follows below. It lasts while the viewport is open (like
  fullscreen, kept over a rotation, never stored); the camera is saved Big, the side cameras are only drawn small. Phones
  never see it. `:core`: `CameraGrid.partial`, `CameraViewport.withPartial`.
- **The phone never names a service or an entity.** It sends `portico/content/run {action_id}` and
  `portico/content/snapshot {camera_id}` with ids from its own profile; the plugin makes the call itself,
  as that phone's user, only if the id is in that phone's profile (the profile is the grant). A test fails
  the build if the app's code builds a `call_service` or names a service.
- **Pictures** come over the same WebSocket (base64, one still per camera every 4 seconds while Home is
  visible and connected), so they work over the tailnet too. Nothing runs while Home is not visible.
  A picture is kept in memory only and is never shown once the link is down.
- **Not connected:** the saved tiles stay, every button is off, no picture is shown, and a line says so.
  Nothing is queued: a button pressed with no connection sends nothing and says so. Paused, not
  configured, a refused token or address, a server too old to send content, and "this phone is not an
  enrolled Portico phone" each have their own line. All of it is `:core`'s `HomeModel`, tested on the JVM.
- **"Asks first"** (the default for a lock or a gate) opens a confirmation before anything is sent. The
  plugin does not rely on it; it is the user's safety net. Each press shows its result for 20 seconds:
  done, not connected, ran a moment ago, unavailable, not allowed, or could not be run.
- **Connection status, in the top bar** (like the intercom app's): a dot over a word. The **colour is the
  health** and the **word is the route or the reason**: green `●` only when Home Assistant is answering (the
  socket has authenticated and `portico/version` answered contract 3), with "LAN" or "Tailscale" under it (the
  tailnet is not a degraded state, so it is as green as the LAN; "LAN" is the direct path, a connection straight to `ha_url`); amber `○` "connecting"; red `○` "offline"
  (retrying), "not set up", "token refused" or "bad address". While paused the **title** says "PAUSED until
  14:30" in amber and the word is "paused": paused is not a fault. Tapping it opens Settings, where the per-path
  reasons are. Every rule is `:core`'s `ConnectionModel` (`ConnectionStatusTest`).
- **Saved profile:** the last profile (names, ids and flags only, in the plain state prefs, never anything
  secret) is shown at once on the next start, before the socket is up. A new enrollment clears it.
- The content commands are in the vendored contract (`ws_v3.json`, 156 cases, replayed by
  `WsContractReplayTest`): `content get`, `content run`, `content snapshot` and `content/subscribe`'s
  `content_changed` event. `PorticoLink` fetches the profile once the session starts and again on a
  `content_changed` whose `rev` differs from the one it holds.

## Pages and the saved document

- **Pages (A2).** A document with two or more pages shows a tab strip (the page labels, scrolling sideways) under
  the status line, and a swipe left or right (mostly horizontal, at least 96 dp, started anywhere but the tab strip)
  moves between pages without wrapping. One page or none: no strip. Only the selected page is drawn and only its
  cameras are fetched. The selection is kept by page id across a refresh and a rotation; a page the editor
  removed falls back to the first. The title is `home_name` when sent, else `Portico`. "Nothing to show yet" appears
  only when **every** page is empty. Labels are plain text: control and bidi characters are dropped, whitespace
  collapses, a camera/button/door name is cut at 60 characters and a tab at 24; a blank label shows the id (a tab, its
  position). All of it is `:core`'s `Pager`, `Swipe`, `Label` and `HomeModel` (`ScreenModelTest`).
- **The saved document (A2).** The whole resolved document (pages, callers, roster) is cached as ONE JSON blob in the
  plain state prefs (`ContentCodec`, blob version 2; names, ids and flags only), read when the app starts so Home shows
  at once and then refreshed by `content/get`. The older flat blob (version 1: contract 2's ids, which no longer exist on
  the server) is dropped on the first read, not migrated.
